# Product

## Platform
web

## Users
The user is learning RAG by building and inspecting every stage on local documents. Confirmed by the conversation and the request for explanations throughout the application.

## Product Purpose
RAG makes document extraction, chunking, embedding, indexing, retrieval, graph construction, generation and evaluation observable and comparable.

## Operating Context
Existing Next.js/React frontend and Python/FastAPI/SQLAlchemy backend in D:/RAG-I, with local files and optional configured model services. Existing projects and results must survive the redesign.

## Capabilities and Constraints
Controls must execute real configured methods. Model-generated explanations and relations must be distinguished from source evidence. Available services, missing prerequisites, timing, tokens and uncertainty must be visible. Keep the historical 10,000-character scale-test boundary.

## Product Principles
- Explain inputs, transformations and outputs beside the working tool.
- Preserve immutable recipes, isolated experiment indexes and frozen evaluation questions.
- Guide the common path while keeping advanced controls available.
- Link visualizations to real source chunks and measured outputs.

## Confirmed Default
The user selected guided learning with explanations and advanced controls.
